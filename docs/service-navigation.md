Owner: `typescript/scripts/lib/service-navigation.ts`; explicit reviewed page records: private `config/service-navigation.json`. Compiled `scripts/lib/service-navigation.js` is generated by `npm run compile`, never edited directly. Public styling lives in `assets/css/service-navigation.css` using the existing site tokens.

`languageShell` applies customer voice, then maintained navigation after normal EN/ZH rendering. The same `trailFor` records generate visible `nav > ol > li` and one BreadcrumbList; existing enrichment retains Organization, LocalBusiness, Service, Article and WebPage, linking the latter to the stable breadcrumb ID. Homepage emits neither a one-node trail nor BreadcrumbList. No pathname-to-slug hierarchy inference or runtime translation occurs.

## Updating content relationships

Update both real language records when adding a page or changing its relationship. Fields include page ID, canonical route, language, page type, service group, existing commercial owner, real parent, short label, language counterpart, index directives and content evidence. `related_owner_urls` are contextual service choices: an installation alternative in a repair guide does not mean that installation owns the entire guide. Confirm against actual body content and the latest approved query-routing rules, not the oldest CSV or contact-form parameters.

Single-service guides/cases may use a service parent. Mixed-trade guides retain the useful guides directory; mixed cases retain homepage ancestry because there is no standalone projects index. Do not invent a projects URL or use a hash fragment as a canonical parent. The repair-example panel never turns surface resealing photographs into shower-screen replacement evidence.

Priority service records expose missing direct homepage entries immediately after the existing popular services. Window repairs already has an entry, so it is not duplicated there. Related services are clearly labeled; owner pages show associated guides/examples; every parent has a real link back to its child. Preserve URL, H1, canonical/hreflang, media, prices, business identity and enquiry implementation.

Adding or changing a parent must update its real visible child entry as well. `validateMap` refuses cycles, missing/unindexable/cross-language parents and owners, inconsistent canonical paths or nonreciprocal language mappings. Tests validate initial HTML, path/schema parity and reciprocal parent links across all current pages.

## Analytics and measurement

Existing `typescript/assets/js/analytics.ts` owns one delegated, idempotent handler. `breadcrumb_click` contains only sanitized source_path, target_path, locale, position, owner_id; no query string, fragment or customer fields. It is a navigation event, not a lead or ranking signal. Existing generate_lead, contact_form_error and phone_click semantics remain intact. Numeric GA4 property/admin access is not configured here; event custom dimensions and lead/key-event settings must be reviewed in the actual property by an authorized operator, not invented locally.

Use actual anchor graphs for click distances and unique source-page support. Separate body, navigation and breadcrumb links; count one source page once in the union. Language-switch links do not shorten same-language click distance. Saved baseline and comparison live in `../reports/breadcrumb-leads-2026-10-20/`.
